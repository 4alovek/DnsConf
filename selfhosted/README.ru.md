# Замена NextDNS на AdGuard Home

VPS обслуживает DNS, а GitHub Actions ежедневно собирает полный фильтр GeoHide.
Никаких ключей VPS или API NextDNS для этого не нужно. Это замена DNS-записей;
приватные настройки и списки блокировки из профиля NextDNS автоматически не переносятся.

## 1. Подготовка VPS

Нужны Docker с Compose и домен, например `dns.example.com`, с A-записью на VPS.
Получите действующий TLS-сертификат для этого домена любым используемым вами способом.
Создайте `selfhosted/certs/fullchain.pem` и `selfhosted/certs/privkey.pem`.
Секретные файлы и данные AdGuard исключены из git. При обновлении сертификата
обновите эти файлы и перезапустите контейнер. Не используйте самоподписанный
сертификат для системного Private DNS Android.

```sh
git clone https://github.com/4alovek/DnsConf.git
cd DnsConf/selfhosted
mkdir -p certs
# Поместите сертификат и ключ в certs перед включением TLS.
docker compose up -d
```

Порты 443/TCP и 853/TCP должны быть свободны. Обычный DNS доступен только
на loopback:5353, панель — через SSH-туннель. Не открывайте 53/UDP в интернет.

На своем компьютере:

```sh
ssh -L 3000:127.0.0.1:3000 -L 8080:127.0.0.1:8080 user@VPS_IP
```

Откройте http://localhost:3000. В мастере выберите веб-интерфейс на порту **80**,
DNS на порту **53**, адрес прослушивания **0.0.0.0** внутри контейнера, задайте пароль.
После мастера панель доступна на http://localhost:8080.

## 2. Настройка AdGuard Home

- В настройках DNS задайте доступный с VPS upstream, например `1.1.1.1` и `9.9.9.9`.
- В настройках шифрования включите TLS, имя сервера `dns.example.com`, DoT **853**,
  HTTPS **443**, пути `/certs/fullchain.pem` и `/certs/privkey.pem`.
- Ограничьте 443/853 своими IP через сетевой firewall провайдера VPS. Для телефона
  с меняющимся IP используйте поддерживаемые AdGuard Home Client ID: в разрешенных
  клиентах укажите выбранные идентификаторы и подключайтесь через
  `phone-id.dns.example.com` (DoT) / `https://dns.example.com/dns-query/phone-id` (DoH).
  Для DoT нужен DNS и сертификат, покрывающий это имя, обычно wildcard.
  Не включайте «разрешать всем», если нужен личный DNS.

## 3. Включение обновлений

После слияния изменений в `main`, в GitHub Settings → Environments → DNS:

- Установите переменную **DNS=SELFHOSTED** (именно в верхнем регистре).
- Сохраните `hosts_exclude`, `REDIRECT`, `EXCLUDE_REDIRECT`, при необходимости `BLOCK`.
  Пустой `REDIRECT` означает официальный hosts GeoHide. `DONOR_DNS` нужно очистить:
  этот режим использует IP непосредственно из hosts.
- Запустите Actions → **Update self-hosted GeoHide filter** → Run workflow.
  Workflow нужен доступ Contents: write; правила защиты main должны допускать
  коммит generated-файла от GitHub Actions.

В AdGuard Home → Фильтры → Черные списки DNS → Добавить список → Пользовательский:

```text
https://raw.githubusercontent.com/4alovek/DnsConf/main/selfhosted/geohide-filter.txt
```

Установите интервал обновления фильтров **1 час** (параметр `filters_update_interval: 1`).
Первый раз нажмите «Проверить обновления». GitHub собирает фильтр в 04:30 МСК;
AdGuard получает его в течение своего интервала, с учетом доступности GitHub.
Удаленные записи исчезают при обновлении полного фильтра. SHA `.geohide-commit`
в этом режиме не используется: ежедневно проверяется содержимое всех источников
и текущие исключения, коммит создается только при изменении результата.
При ошибке загрузки или разбора рабочий опубликованный фильтр сохраняется.

## 4. Подключение и проверка

Android: «Частный DNS» → имя вашего DoT-сервера.
В браузере или DNS-клиенте: `https://dns.example.com/dns-query` (с Client ID, если включен).
Настройте остальные устройства на этот сервер.

На VPS, если установлен `dig`:

```sh
dig @127.0.0.1 -p 5353 chatgpt.com A
dig @127.0.0.1 -p 5353 chatgpt.com AAAA
dig @127.0.0.1 -p 5353 example.org A
```

Сверьте A с актуальным фильтром, проверьте журнал AdGuard: GeoHide должен быть
источником переписывания. Для IPv4-редиректов AAAA возвращает пустой ответ;
родные IPv6/HTTPS-записи не должны обходить редирект. Правила действуют также
на поддомены, `EXCLUDE_REDIRECT` исключает их из переписывания.

Сначала проверьте один клиент, затем переключите остальные. Для возврата выберите
NextDNS на устройствах и восстановите `DNS=NEXTDNS` в окружении GitHub.
Старый workflow перестает обращаться к NextDNS только при `DNS=SELFHOSTED`.
